# 브릿지

물리 `스위치`는 여러 장치를 케이블로 연결해 같은 `네트워크 세그먼트`로 묶어준다.
가상머신/컨테이너는 물리 케이블이 없으니, 이 "묶어주는 스위치 역할"을 소프트웨어로 구현한 게 `브릿지`다.
> 네트워크 세그먼트란 같은 네트워크 대역에 속해, 서로 직접(라우터 없이) 통신 가능한 장치들의 묶음을 말한다.  
> 옛날에는 케이블 하나(segment)에 장치들을 물리적으로 매달아 사용하였고 지금은 논리적으로 대신한다.

### 스위치와의 대응 관계
- 물리 포트 ↔ 브릿지의 인터페이스(veth, tap 등)
- MAC 주소 학습 ↔ 브릿지도 동일하게 MAC 테이블을 만들어 학습함  

즉 "리눅스 커널이 스위치처럼 동작하는 것"이지 튜널링이나 라우팅이 아니다.
> 튜널링이란 하나의 네트워크 데이터를 다른 네트워크 패킷 "안에 통쨰로 감싸서" 전달하는 방식.

## 브릿지 vs 라우팅의 차이
- 브릿지: 2계층(MAC) 기준으로 스위칭 — 같은 네트워크 대역
- 라우팅: 3계층(IP) 기준으로 경로 결정 — 다른 네트워크 대역 간 연결

이 구분이 중요한 이유는, 브릿지에 물린 장치들은 모두 같은 서브넷(같은 IP 대역)을 써야 하고,  
별도 라우팅 설정 없이도 서로 통신 가능하기 때문이다.

## 실제 동작
브릿지에 물린 물리 인터페이스(예: enp6s0)는 더 이상 자기 IP를 직접 안 갖고,
브릿지 쪽이 IP를 가짐 — 물리 카드는 순수하게 "전달 통로"로만 동작

## 브로드캐스트 도메인
브릿지로 묶인 장치들은 하나의 브로드캐스트 도메인을 공유한다.
즉 한 장치가 "전체한테 뿌리는" 패킷(ARP 요청 등)을 보내면,
브릿지에 물린 모든 장치가 그걸 받는다.  

- 장점: 설정 없이 서로 바로 통신 가능 (같은 스위치에 꽂은 것처럼)
- 단점: 장치 수가 늘어날수록 불필요한 브로드캐스트 트래픽도 늘어남
  (이걸 나누고 싶을 때 VLAN을 씀 — 브릿지 하나를 논리적으로 여러 개처럼 쪼갬)

## 왜 컨테이너/VM 환경에서 표준으로 쓰일까
- 각 VM/컨테이너 입장에서는 "물리 스위치에 꽂힌 독립된 장치"처럼 보임
  → 게스트 OS 입장에서 자기가 가상 환경인지 신경 쓸 필요 없음
- Docker의 기본 네트워크(docker0)도 같은 원리의 브릿지
