# 변수명 컨벤션

## 최적의 길이
변수명이 너무 짧으면 의미를 파악하기 어렵고,  
그렇다고 너무 길면 변수명을 해독하느라 중요한 로직이 눈에 안 들어올 수 있다.
```
# 너무 긴 유형
numberOfPeopleOnTheUsOlympicTeam
numberOfSeatsInTheStadium

# 너무 짧음
x
max
sum
```
통계적으로 변수명의 길이는 8자에서 20자 사이가 디버깅에 용이하다고 한다.
```
teamMemberCount
teamPointsMax
```

### 짧은 변수명은 나쁠까?
변수명이 짧다고 무조건 나쁜 것은 아니다.
```java
for (int i = 0; i < userActiveList.size(); i++) {
  User user = userActiveList.get(i);
}
```
다음과 같이 제한된 범위와 적절한 범위에서 **임시 값**으로 사용되는 경우에는 짧아도 어떤 의도로 사용되는지 파악하기가 쉽다.

> W.J 한센의 연구에서 지역 변수나 반복문에서는 오히려 더 좋다는 결과도 있다.

## 전역 변수에는 한정자를 붙여보자.
전역변수들은 어디에서 사용될 지 모른다.

그렇기에 **명확히** 어떤 역할을 하는지 어떤 용도인지를 어디서도 알 수 있게 작성하는게 좋다.
``` java
// 어디에 무슨 용도인지 문맥이 전혀 없다.
int count = 100;
String name = "Main";

// 조금이라도 더 자세하게 어떤 용도인지 알기쉽게 작성하자.
int totalUserCount = 100;
String systemMainMenuName = "Main";
```
또한 변수 이름에 계산값 **한정자**가 붙는다면 이름 끝에 붙여보자.
``` java
int employeeTotal = 100;
int totalEmployee = 100;
```
이러한 습관이 다음과 같은 장점이 있다고 말한다.  
  1. 이름상 의미는 같지만 규약을 통해 **혼란을 방지**하자.
  2. 보통 전달하고자 하는 의미는 앞부분에 있기에 가장 눈에 띄고 파악하기 쉽게 만든다.
  3. 이름이 보기 좋은 대칭을 이룬다.
> 사실 제일 중요한건 프로젝트에서의 **일관성**이라고 생각한다. 기존 개발자들이 해둔 방향성을 최대한 맞추거나 본인의 스타일에 맞추게 설득을 하는등 **일관성**이 핵심이다.

그리고 변수명들은 반의어를 사용하여 일관성을 유지하고 가독성을 높이는데 도움을 줄 수 있다.

 - begin/end
 - first/last
 - min/max
 - source/target
 - next/previous

> 변수명 짓는건 매번 어렵지만 적어도 본인만의 기본적인 습관을 가지고 있는게 좋다고 생각한다.
나같은 경우는 계산값(sum, average 등) 한정자들은 이름 끝에 붙이려고 하는 편이다.
