# 변수명 지어보기

## 열거형
많은 언어들에서 열거형(enum)을 지원한다.
```c
enum Color {
  Color_Red
  , Color_Blue
  , Color_Green
}
```
앞에 열거형을 다시 접두사로 적음으로써 하나의 그룹에 속한다는 것을 보장하면 좋다.

다만 열거형을 클래스처럼 다루는 경우에는 다음과 같이 할 수 있다.
```java
enum Color {
  RED, BLUE, GREEN
}

Color c = Color.RED
```
열거형 이름 자체를 접두사로 간단하게 처리 가능한 언어들이 많고,  
이런 경우에는 접두사로 적는 것은 의미가 없기에 생략하는 것이 더 좋다.

## 상수
상수들은 표현하는 추상적인 대상을 나타낼 수 있어야 한다.
```java
// 나쁨 - 이름이 값 자체를 반복할 뿐, 의미가 없음
int FIVE = 5;

// 최악 - 이름과 값이 불일치해서 혼란을 유발함
int FIVE = 6;

// 좋음 - 5가 "무엇"을 의미하는지 이름에서 드러남
int DAILY_DONUT_RESTOCK_COUNT = 5;
```

## 이름 규약
규약은 사실 없는거보단 있는게 좋다는 말에 동의한다.

그 규약이 말도 안되거나 이상할 수도 있지만 아무런 규약없이 진행되는 프로젝트는  
오히려 산으로 갈 확률이 높다고 생각한다.

요즘은 하나의 프로젝트에 여러개의 언어를 같이 사용한다.  
이럴수록 더 기본적인 원칙을 지켜보려고 해보자.
- 완벽함보다는 프로젝트내의 일관성을 지키자.
- 각 언어별 고유 관례(Java camelCase vs Rust snake_case)는 존중하되,  
  언어 관계없이 통일 가능한것들은 통일하자.

## 피해야할 변수 이름
### 유사한 의미가 있는 이름은 피하자.  
input과 inputValue, recordNum, numRecords와 같이 의미상 너무 유사하여  
같은 코드내에서 사용시 혼동하기 쉬워 오류가 발생할 소지가 높다.

### 이름에 숫자를 넣는 것을 피하자.
file1, file2 와 같이 변수 끝에 넣어 구별하는 방법보다 더 나은 대안을 찾아보자.

차라리 배열에 넣어 사용하는 대안도 있기는 하다.

### 여러가지 자연어를 사용하지 말자.
모든 코드에 한가지 언어만 사용을 하자.
```js
let 사용자조회결과 = [];
let activeUserList = 사용자조회결과.filter(사용자 => 사용자.isActive);
```
이렇게 여러 언어로 작성할 경우 같은 언어권 국가이더라도 혼란을 야기할 수 있다.

### 읽기 어려운 문자를 포함하지 말자.
`eyeChart1`, `eyeChartI`, `eyeChatrtl` 과 같이 헷갈리기 쉬운 이름은 지향하자.

> 결국 이 모든 규칙들은 **읽는 사람**이 한 번에 이해할 수 있도록 작성하는 것이다.
