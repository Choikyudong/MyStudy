# 반복문

사람들마다 반복문 작성시 기준은 다를것이며 아래에서 공감되거나 좋다고 생각하는 부분만 이용하자.

1. 반복문에는 `{`와 `}`로 감싸자.  
   `코드블록`은 실행 시 비용이 들지 않지만 가독성을 높여주는데 좋은 도움을 준다고 생각한다.

2. 반복문이 종료되는지 재확인.  
   당연한 이야기지만 `모든 상황`에서 반복문이 종료되는지 `확신`이 될때까지 마음속으로라도 반복문을 실행하자.

3. `for`문 종료를 위한 조작 코드를 작성 하지말자.  
   ```text
   for (int i = 0; i < 100; i++) {
       // ...
       
       if ( ... ) {
           i = 100;
       }
       
       // ...
   }
   ```
   위 코드는 읽는 사람을 혼란스럽게 만들어 버그를 생성하게 만드는 좋지않은 습관이라고 생각한다.
   > 사실 적으면서 이런 케이스가 정말 흔할까라는 생각은 들긴함..

4. 외부에서도 사용되야 한다면 외부에서 명시적으로 정의하자.  
   ```
   int recordCount = 0;
   for (; recordCount < recordLength; recordCount++) {
       // ...
   }
   
   // ... 수십줄의 코드들
   
   if (recordCount > LIMIT_COUNT) {
       // ...
   }
   ```
   문법적으로 기능상으로 틀리지는 않았으나 해당 코드를 읽으면서 반복문에서 어떻게 되었는지,  
   모든 라인을 다 읽어야 되는 상황이 생길 수 있다.

   ```
   int finalCount = countRecords(...);
   
   // ... 수십 줄 ...
   
   if (finalCount > LIMIT_COUNT) {
       // ...
   }
   ```
   명시적으로 변수로 분리하는 식으로 처리해보자.
   > 꼭 함수로 분리해서 처리를 해라는 말은 아님..
   
5. 반복의 길이는 한눈에 볼 수 있을 정도로 짧게 만들자.  
   많은 사람들은 반복문 내부의 길이가 `20줄`을 넘어가면 길다고 느낀다.

6. 중첩을 3단 이하로 제한하자.  
   중첩이 많아질수록 경우의 수도 그만큼 늘어나 뇌 부담도 그만큼 늘어난다.  
   최대한 짧게 3단 이하로 적자.
   > 사실 3단도 이미 부담스럽긴 하다..
